# Repository and Identifier Selection

Choose the access route before drafting the statement. Match the repository to data
type, community practice, access requirements, file size, versioning, metadata, and
identifier support. Prefer a maintained domain repository when it offers the expected
accession and metadata model; otherwise use a durable general repository.

Track deposit state separately from access route:

- `planned`: target selected, upload or identifier not yet created;
- `pending`: deposit exists but review, release, or accession is incomplete;
- `complete`: location and persistent identifier have been verified; and
- `not-applicable`: no external deposit is required, with a stated reason.

Never write a planned DOI or accession as if it exists. Record repository name, record
URL, persistent identifier, version, release date or embargo, licence, and access
contact only when verified.

Use controlled access for a documented ethical, legal, privacy, commercial, or
third-party constraint. Name the responsible access body, criteria, expected response
route, and applicable conditions when known. Do not use “reasonable request” as a
substitute for an access mechanism.

For reused datasets, cite the original dataset record and state the version or access
date. For code, distinguish archived release from a moving development branch. For
source data behind figures, map every quantitative panel to an exact file and column or
sheet rather than citing only a repository landing page.
